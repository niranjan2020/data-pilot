# SQL Safety & AST Validation

Data Pilot now has a SQLGlot-based `SQLGlotValidator` implementing the `SQLValidator` contract.

## Boundary

The intended execution path is:

```text
SQL generated by a future template/LLM
        ↓
SQLValidator
        ↓
DatabaseProvider.execute_query()
```

The validator does not execute SQL and does not need database credentials.

## Current rules

- Exactly one SQL statement is allowed.
- Only read-oriented `SELECT`, `UNION`, `EXCEPT`, and `INTERSECT` roots are accepted.
- Mutating AST nodes such as `INSERT`, `UPDATE`, `DELETE`, `CREATE`, `DROP`, `ALTER`, `MERGE`, `TRUNCATE`, `GRANT`, and `REVOKE` are rejected.
- Mutating nodes inside a CTE are also rejected.
- The parser dialect can be supplied explicitly; PostgreSQL is the default.
- Referenced tables are extracted from the AST.
- A `SELECT` without `LIMIT` produces a warning rather than an automatic rejection.

## Important security model

AST validation is a deterministic application-level boundary. The PostgreSQL provider's read-only transaction boundary remains a second defense. Both layers are intentional: the validator prevents unsafe SQL from progressing through the application, while the database provider enforces read-only execution at the connection level.

The validator will be extended later with resource/cost policies, allowed-schema/table policies, and dialect-specific rules. Those should be added without weakening the basic read-only boundary.

## First end-to-end milestone

The repository is not yet at the first natural-language end-to-end test. The remaining core pieces are:

1. LLM provider adapter.
2. Semantic catalog: business concepts, synonyms, entities, metrics, rules, and templates.
3. NL-to-SQL orchestration that selects semantic context, generates SQL, validates it, and executes it.
4. A small API endpoint and an end-to-end test fixture using local PostgreSQL.

At that point we can test a real question such as:

```text
"How many vessels are operated by MSC?"
        ↓
intent / semantic resolution
        ↓
template or SQL generation
        ↓
AST validation
        ↓
PostgreSQL execution
        ↓
structured result
```

This milestone intentionally comes before SaaS work and does not require multi-tenancy, billing, authentication, or cloud infrastructure.
